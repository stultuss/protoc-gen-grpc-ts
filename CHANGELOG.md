# Changelog

All notable changes to this project will be documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [4.1.0] - 2026-08-11

### Added

- Differential test (`npm run test:differential`): regenerates the corpus with
  the bundled protoc + grpc_node_plugin and verifies the generated `.d.ts`
  mirrors the real runtime JS surface (instance/static methods, enum members,
  extensions, service paths and method keys). It requires the bundled
  binaries and runs locally, not in CI.
- README "Compatibility" section documenting the supported runtime and
  toolchain boundaries (jspb 3.x, protoc 3.19.1, Node.js >= 18, x64 binaries).

### Changed

- `@grpc/grpc-js` is no longer a runtime dependency of the generator itself;
  projects consuming the generated files install it themselves.
- The `protoc-gen-grpc*` bin wrappers now propagate protoc's exit code and
  report spawn failures cleanly instead of throwing an uncaught exception.
- The install-time binary download is now verified against pinned sha512
  checksums before extraction, replacing `@mapbox/node-pre-gyp` (which
  performed no integrity check) with a small bundled installer.
- CI gained an `e2e` job that installs with lifecycle scripts enabled and
  runs the generator against the real bundled protoc toolchain, covering the
  binary download, the differential test, and the bin wrappers.

### Removed

- Legacy `grpc` runtime support. Generated `.d.ts` files always import
  `@grpc/grpc-js` now; the `grpc_js` `--ts_out` parameter is accepted for
  compatibility and ignored. The legacy `grpc` package is deprecated and
  cannot be installed on current Node.js, so its output could never compile.

## [4.0.0] - 2026-08-07

This is a major release: relative to 3.0.0 the generator was rebuilt around a
new feature set, every generated `.d.ts` now carries a version header, and the
published package, dependencies and Node.js floor all changed. Upgrade by
regenerating your protobuf outputs and bumping Node.js to >= 18.

### Added

- proto3 `optional` field support (`hasXxx()` / `clearXxx()`, nullable getters
  and `AsObject` entries)
- `[jstype = JS_STRING]` support: `int64`/`uint64` fields map to `string` to
  avoid precision loss
- Version header on every generated `.d.ts`:
  `// Code generated by protoc-gen-grpc vX.Y.Z. DO NOT EDIT.`
- Comma-joined `--ts_out` parameters (e.g. `grpc_js,keep_case`)
- `oneof` groups: `get<Name>Case()` accessor and `<Name>Case` enum
- 92 unit tests with golden baselines, run automatically on GitHub Actions
  (Node.js 20 and 22)

### Changed

- Generation errors are reported through `CodeGeneratorResponse.error` instead
  of `process.exit(1)`, with file/message/field context
- `@grpc/grpc-js` upgraded to 1.14.x; TypeScript to 5.9; minimum Node.js is now
  18 (previously 16)
- Published package slimmed from ~3.3 MB to ~14 kB via a `files` whitelist;
  `build/` is no longer committed (rebuilt by `prepare` before publishing)
- `@mapbox/node-pre-gyp` is bundled as a runtime dependency so the binary
  download works after `npm install`

### Fixed

- Proto files without a package now resolve top-level and nested messages and
  enums correctly
- `google/api/annotations.proto` is filtered consistently in message and
  service files
- Field names like `extension` / `JsPbMessageId` get a `$` suffix
  (`getExtension$()`), matching the generated JavaScript
- Proto3 `optional` no longer emits synthetic oneof `Case` enums
- npm 11 `allow-scripts` behaviour no longer breaks the install-time binary
  download

### Breaking / upgrade notes

- Generated output changes: a version header is prepended to every `.d.ts`;
  proto3 `optional` fields are typed as nullable (`?` / `| undefined`);
  `[jstype = JS_STRING]` fields become `string`
- Requires Node.js >= 18
- Regenerate all protobuf outputs after upgrading
